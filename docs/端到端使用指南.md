# sql-mask 端到端使用指南（47.100.166.158 实战环境）

> 本文是《使用手册》的实操篇：描述远程演示环境的部署实况，并给出浏览器、
> REST、CLI 三条端到端路线的逐步操作。全部步骤均在环境中验证过。
>
> 环境基线：sql-mask `full-test` 分支提交 `05c1be9`；2026-09-24 该 ECS 系统
> 被重置后按**原生架构**整体重建（无 Docker）：apt 安装 PostgreSQL 16 与 nginx，
> 四服务以 systemd 常驻（Ubuntu 24.04，2C/1.6G + 2G swap）。

## 1. 环境实况

### 1.1 端口与入口

| 端口 | 组件 | 公网可达 |
|---|---|---|
| 22 | sshd | ✅（仅此 + 80，其余被安全组拦截） |
| 80 | nginx（管理台前端静态资源 + /api 反代） | ✅ **浏览器入口 http://47.100.166.158** |
| 5432 | PostgreSQL 16（原生，`postgres/PgTest2026`，仅监听本机） | ❌ 安全组拦截，走 SSH 隧道（见 §8） |
| 8080 | mask-core 改写服务 | ❌（本机 curl 或隧道） |
| 8081 | mask-policy-server 策略服务 | ❌ |
| 8082 | mask-metadata 元数据服务 | ❌ |
| 8083 | mask-query 查询服务 | ❌ |

nginx 站点配置在 `/etc/nginx/sites-available/sqlmask.conf`：`/api/instances`、
`/api/effective` → 8081；`/api/meta/**`（重写为 `/api/**`）→ 8082；`/api/v1/` → 8083；
`/api/risk/` → 8084（risk 服务未部署，相关控制台页签不可用）；其余 `/api/**` → 8080；
`/` 为 SPA 静态资源 + 深链回退。

### 1.2 数据库（原生 PostgreSQL 16 集群 main，三个库）

| 库 | 用途 |
|---|---|
| `crm` | 业务演示数据：customer(50 行)/orders(120 行，north 26 行)/other(10 行)/archive(写入演示) |
| `mask_policy` | 策略服务持久库（schema.sql 自动建表） |
| `mask_metadata` | 元数据服务持久库（metadata-schema.sql 自动建表） |

### 1.3 预置脱敏 UDF（crm 库 public schema，验证输出示例）

| UDF | 签名 | 效果示例 |
|---|---|---|
| mask_phone | (text, int, int) | `mask_phone('13812345678',3,4)` → `138****5678` |
| mask_email | (text) | `mask_email('zhangsan@qq.com')` → `z***@qq.com` |
| mask_name | (text) | `mask_name('张三丰')` → `张*丰` |
| mask_idcard | (text, keep default 4) | `mask_idcard('330102…1234')` → `330102********1234` |
| mask_hash / mask_text / mask_custom | (text[, algo]) | 摘要哈希 / 等长打星 / 哈希前缀 |

### 1.4 已注册的演示实例与策略（实例名 `crm_pg`，方言 postgresql）

- **UDF 签名**（与 crm 库列类型精确对应，策略服务按「名字+参数类型」校验）：
  `mask_phone(varchar(20),integer,integer)`+`mask_phone(bigint,integer,integer)`、
  `mask_email(varchar(100))`、`mask_name(varchar(50))`、`mask_idcard(varchar(18),integer)`
- **策略**（5 条）：

| 策略 | 类型 | 资源 | 主体 | 内容 |
|---|---|---|---|---|
| mask-customer-phone | DATAMASK | customer.phone | groups `*` | mask_phone(3,4) |
| mask-customer-email | DATAMASK | customer.email | groups `*` | mask_email |
| mask-customer-idcard | DATAMASK | customer.id_card | groups `*` | mask_idcard(4) |
| mask-customer-name | DATAMASK | customer.name | groups `*` | mask_name |
| analyst-north-only | ROW_FILTER | orders（表级） | groups `analysts` | `region = 'north'` |

- **三主体生效差异**（`GET /api/effective/crm_pg` 实测）：

| 主体 | 掩码列 | 行过滤 |
|---|---|---|
| alice（devs） | 4 列全掩码 | 无 |
| bob（analysts） | 4 列全掩码 | orders 只留 north |
| 匿名 | 4 列全掩码 | 无 |

## 2. 路线 A：浏览器全流程（推荐）

1. 打开 **http://47.100.166.158** → 总览页。
2. 进 **设置**：管理 Key 填 `local-admin-key`，数据 Key 填 `local-data-key`，保存（存 localStorage）。
3. **访问管理**：按方言分组的实例网格 → `postgresql` 分组可见实例 `crm_pg`
   （没有就点「新建」：名称 crm_pg、方言 postgresql）→ 点卡片进 **策略管理器**。
4. **策略管理器** 四页签：
   - 策略：可见 5 条策略（4 条 DATAMASK + 1 条 ROW_FILTER），绿色 Add New Policy 可加新策略；
   - 资源/表结构：customer/orders/other/archive 四表 22 列；
   - 脱敏 UDF：4 个已注册 UDF 及其签名；
   - 生效配置：填 `user=bob`、`groups=analysts` 拉取 → 应看到 4 掩码列 + orders 行过滤。
5. **改写试验台**：选 instance 模式、实例 `crm_pg`，输入：
   ```sql
   SELECT c.name, c.phone, c.email, c.id_card
   FROM customer c WHERE c.id <= 3 ORDER BY c.id
   ```
   执行 → 结果卡片显示「已脱敏（外层包装 UDF）」，展开可见改写 SQL：
   ```sql
   SELECT mask_name(r.name) AS name, mask_phone(r.phone, 3, 4) AS phone,
          mask_email(r.email) AS email, mask_idcard(r.id_card, 4) AS id_card FROM (
   SELECT c.name, c.phone, c.email, c.id_card
   FROM customer c WHERE c.id <= 3 ORDER BY c.id
   ) AS r
   ```
6. **审计**：本环境未部署 Elasticsearch（内存所限，`AUDIT_ENABLED=false`），审计页
   会提示不可用（502 `AUDIT_SEARCH_UNAVAILABLE`）——这是预期行为，业务不受影响。
7. （可选）**playground 内联模式**：不带实例、直接贴 metadata YAML 体验无策略服务的纯改写。

## 3. 路线 B：REST 全流程（SSH 到主机执行）

```bash
ssh root@47.100.166.158     # 或从本地走隧道，见 §8
```

### 3.1 元数据服务：登记实例 + 在线采集

```bash
BASE=http://127.0.0.1:8082; H='-H X-Api-Key:local-dev-key -H Content-Type:application/json'
# 登记（密码用环境变量名引用；engine 由 dialect 派生，只有 starrocks 需要显式 engine）
curl -s $BASE/api/instances $H -d '{
  "name":"crm_pg","dialect":"postgresql",
  "connection":{"host":"127.0.0.1","port":5432,"database":"crm",
                "dbUser":"postgres","passwordRef":"SQLMASK_DS_CRM_PASSWORD"}}'
# 采集 → {"tableCount":4,"columnCount":22,"warnings":[],"metadataVersion":2}
curl -s -X POST $BASE/api/instances/crm_pg/collect $H
```

### 3.2 策略服务：导入表结构 → 注册 UDF → 建策略

```bash
PS=http://127.0.0.1:8081; A='-H X-Api-Key:local-admin-key -H Content-Type:application/json'
# 一键导入（自动创建实例，方言取自快照）
curl -s -X POST $PS/api/instances/crm_pg/import-metadata $A -d '{
  "metadataBaseUrl":"http://127.0.0.1:8082","metadataApiKey":"local-dev-key","metadataInstance":"crm_pg"}'

# 注册 UDF（首参必须与列类型精确相等，如 varchar(20)；同义重载并列声明）
curl -s $PS/api/instances/crm_pg/udfs $A -d '{
  "name":"mask_phone",
  "signatures":[{"params":["varchar(20)","integer","integer"],"returns":"varchar"},
                {"params":["bigint","integer","integer"],"returns":"varchar"}]}'

# 建 DATAMASK 策略（对所有人脱敏手机号）
curl -s $PS/api/instances/crm_pg/policies $A -d '{
  "name":"mask-customer-phone","policyType":"DATAMASK","isEnabled":true,"priority":0,
  "resource":{"catalog":"crm","schema":"public","table":"customer","columns":["phone"]},
  "subjects":{"users":[],"groups":["*"]},"udf":"mask_phone","arguments":[3,4]}'

# 建 ROW_FILTER 策略（analysts 只看 north 区订单）
curl -s $PS/api/instances/crm_pg/policies $A -d '{
  "name":"analyst-north-only","policyType":"ROW_FILTER","isEnabled":true,"priority":0,
  "resource":{"catalog":"crm","schema":"public","table":"orders"},
  "subjects":{"users":[],"groups":["analysts"]},"filterExpr":"region = '"'"'north'"'"'"}'
```

### 3.3 改写服务：instance 模式

```bash
curl -s http://127.0.0.1:8080/api/rewrite -H 'Content-Type: application/json' -d '{
  "instance":"crm_pg",
  "sql":"SELECT name, phone, email, id_card FROM customer WHERE id <= 3 ORDER BY id",
  "user":"alice","groups":["devs"]}'
# statements[0].rewrittenSql（实测）：
# SELECT mask_name(r.name) AS name, mask_phone(r.phone, 3, 4) AS phone,
#        mask_email(r.email) AS email, mask_idcard(r.id_card, 4) AS id_card FROM (
# SELECT name, phone, email, id_card FROM customer WHERE id <= 3 ORDER BY id ) AS r
```

### 3.4 查询服务：真库执行（端到端闭环）

```bash
Q=http://127.0.0.1:8083/api/v1/query; CT='Content-Type: application/json'; K='X-Api-Key: local-query-key'
# alice：全量行 + 全掩码
curl -s $Q -H "$K" -H "$CT" -d '{
  "instance":"crm_pg","user":"alice","groups":["devs"],
  "sql":"SELECT name, phone, email, id_card FROM customer WHERE id <= 3 ORDER BY id",
  "includeRewrittenSql":true}'
# → rows: [["张*丰","138****5678","z***@example.com","330102********1234"], ...]
#   masked:true rowFiltered:false

# bob：orders 行过滤生效（实测：masked:true rowFiltered:true rowCount:26，全部 north；

curl -s $Q -H "$K" -H "$CT" -d '{
  "instance":"crm_pg","user":"bob","groups":["analysts"],

# → rows 形如 [4, "杨洋", "133****2585", "north", 63.38]
```

## 7. 引擎侧 UDF（本文环境即 PostgreSQL DDL，源文件 deploy/local-e2e/01_udf.sql，主机副本 /opt/sqlmask/01_udf.sql）

```sql
CREATE OR REPLACE FUNCTION mask_phone(v text, front integer, back integer)
RETURNS text LANGUAGE plpgsql IMMUTABLE STRICT AS $$
DECLARE n integer := length(v);
BEGIN
  IF n <= front + back THEN RETURN repeat('*', n); END IF;
  RETURN substr(v, 1, front) || repeat('*', n - front - back) || substr(v, n - back + 1, back);
END $$;
-- mask_email / mask_name / mask_idcard / mask_hash / mask_text / mask_custom 同文件
```

## 9. 已知事项与故障排查

| 事项 | 说明 |
|---|---|
| 审计页不可用 | 未部署 ES（1.6G 内存所限）；`AUDIT_ENABLED=false`，业务不受影响；需要审计时另起 ES 并去掉该 env |
| 5432 公网不通 | 安全组仅放行 22/80；用 §8 隧道或在安全组放行 |
| mask-query 无 `/actuator/health` | 该服务无 actuator（设计如此），进程存活 + `POST /api/v1/query` 应答即健康 |
| hive-jdbc 带进 javax jasper 导致启动崩溃 | 已在 mask-query/pom.xml 排除 `tomcat:jasper-compiler`、`tomcat:jasper-runtime`、`org.glassfish.web:javax.servlet.jsp`（部署机 jar 已含此修复；主线合入时请同步） |
| **小内存主机** | 四服务 systemd 已按真实用量限内存（`MemoryMax`）+ SerialGC 小堆 + `vm.swappiness=15`；重置后已无 MySQL/Docker，实测常驻约 1.1G、可用 500M+，运行稳定 |
| 控制台「风险」页签不可用 | dist 的 nginx 路由含 `/api/risk/` → 8084（mask-risk-server 未部署）；其余页签不受影响 |
| UDF 签名必须精确到类型 | 列 `varchar(20)` ≠ 签名 `varchar`——按采集快照的类型声明写签名 |
| 401 | 检查 X-Api-Key 与 `/opt/sqlmask/env/*.env` 中 Key 是否一致 |
| 服务异常 | `journalctl -u sqlmask-*`、`dmesg | grep -i oom` 定位；`systemctl restart sqlmask-*` 逐个拉起 |

## 11. 本机 WSL 备用环境（Windows 侧）

远端不可用时，本机 WSL2(Ubuntu) 有一套同构栈可随时使用（已配置为 systemd 常驻）：

- PostgreSQL 18（WSL 内 127.0.0.1:5432，`postgres/PgTest2026`，同三库同种子数据）；
- 四服务 jar 在 WSL `/opt/sqlmask/`，systemd 单元 `sqlmask-{core,policy,metadata,query}`（已 enable）；
- 启动方式：任意 `wsl -d Ubuntu` 进入后 `systemctl status sqlmask-*` 确认（VM 冷启动需等 60~90s）；
  WSL VM 在最后一个会话结束约 60s 后关闭，服务随下次进入自动拉起；
- 配置/验证脚本：`/opt/sqlmask/{local-full-e2e,e2e-verify}.sh`（源在仓库 `deploy/local-e2e/`）；
- 注意：本机 WSL 为 NAT 模式且 localhost 转发关闭，Windows 侧程序暂无法直连 WSL 内端口
  （可在 `.wslconfig` 开启 `networkingMode=mirrored` 后解决）；管理台请走 §2 的远端入口。
