# sql-mask 全量功能清单

> 基线：`full-test` 分支（2026-09-24）。本文以代码为准清点仓库全部功能面；
> 使用方法见《使用手册》，已部署环境的实操步骤见《端到端使用指南》。

sql-mask 是基于 Apache Calcite 的多引擎 SQL 脱敏改写服务：把查询改写为
「原始查询作为内层、最外层对结果列调用脱敏 UDF」的 SQL，支持
**PostgreSQL / Trino / MySQL / Hive / Spark SQL** 五种方言（输入输出同方言，
不做跨引擎转写），并提供行级过滤（row filter）、按主体（users/groups）的
Ranger 式策略、元数据采集、受控查询数据面、审计与指标。

---

## 2. 改写内核功能（五方言共享管线：解析→校验→血缘→改写→渲染）

### 2.1 语句与改写语义

- 支持：`SELECT`、`WITH ... SELECT`、`INSERT INTO ... SELECT`、
  `CREATE TABLE [IF NOT EXISTS] ... AS SELECT`；hive/sparksql 另支持
  `INSERT OVERWRITE TABLE ... SELECT`；`SELECT TOP (n)` 全方言可解析；
- **写入语句对“写入的数据”脱敏**（目标表/列清单/`IF NOT EXISTS` 原样保留）；
  `INSERT ... VALUES` 纯字面量直通，VALUES 藏子查询按安全策略失败；
- 引擎自定义函数可直接使用（不透明标量函数，血缘穿透参数）；
- 非递归 CTE、子查询、派生表参与血缘追踪，CTE 内部不插 UDF；
- 脱敏 UDF 只出现在最外层，每命中列只调用一次；内层 WHERE/JOIN/GROUP BY/
  ORDER BY/LIMIT/DISTINCT 等原样保留；`ORDER BY` 可引用投影外列（排序键投影回处理）；
- 多来源列按 `catalog.schema.table.column` 字典序稳定选策略；
- 行过滤叠加时内层注入 `(SELECT * FROM t WHERE <rowFilter>) AS 别名`，
  覆盖 FROM/JOIN/逗号连接/派生表/CTE 体/集合操作分支/表达式子查询/写入源查询；
  同表多处引用每个位置各自注入；目标表永不过滤。

### 2.2 安全失败（fail-closed）清单

- `UPDATE`/`DELETE`/其他 DML/DDL、`WITH RECURSIVE`、根级集合操作；
- 输出位置关联标量子查询（血缘不可证）、需要包装的重复输出列名；
- MySQL：不带 AS 的 CTAS、`ON DUPLICATE KEY UPDATE`、`REPLACE INTO`、
  双引号标识符（直接拒）；Trino：带表属性 CTAS；
- Hive/Spark：CTAS 的 babel 变体、`STORED AS`/`ROW FORMAT`/`USING`/`PARTITIONED BY`；
- 行过滤条件白名单：仅允许声明列引用/字面量/布尔逻辑/比较/`IS [NOT] NULL`/
  `IS [NOT] DISTINCT FROM`/常量 IN/四则运算；函数、子查询、会话函数、动态参数全禁；
- 未知 FROM 形态引用受控表（TABLESAMPLE/LATERAL/UNNEST）、受控表三段名作列前缀。

### 2.3 方言差异速览

| 维度 | PostgreSQL | Trino | MySQL | Hive | Spark SQL |
|---|---|---|---|---|---|
| 标识符引号 | 双引号（按需） | 双引号（按需） | 反引号（包装层一律加） | 同 MySQL | 同 Hive |
| 非引号标识符 | 折叠小写 | 折叠小写 | 不折叠、大小写不敏感 | 折叠小写 | 折叠小写 |
| 两段名 `db.table` | 不支持 | 不支持 | 支持 | 支持 | 支持 |
| `LIMIT offset,count` | — | — | 可解析（MYSQL_5） | — | — |

各引擎类型清单见 README「方言支持」；类型声明回显原样保留，复杂类型声明即拒绝。

## 3. 策略模型（三套来源，互斥）

1. **metadata.yaml 内嵌**（旧格式，对所有人无条件生效）：`policies` / `columns` / `rowFilter`；
2. **policies.yaml**（Ranger 式独立文件，`--policies` / 请求 `policyYaml`）：
   - `dataMaskItems`（列脱敏）/ `rowFilterItems`（行过滤）二选一；
   - 主体 `users`/`groups`，`*` 通配全体；特异性 user > group > `*`；无主体=匿名；
   - 多策略命中：`enabled=false` 跳过 → `priority` 高者 → 声明序；掩码每列唯一命中，
     行过滤按决策顺序 AND 叠加；
   - 资源四级（catalog/schema/table/column）支持 glob（`order_*`、`*_bak`、裸 `*`）；
     模式折叠小写后匹配；必须命中至少一张声明表（fail-closed）；
3. **策略服务 REST 管理面**（8081）：实例/策略/UDF 全 CRUD，资源用精确名
   （含 `*` 的资源显式拒绝），存量策略自动等价全体生效。

## 4. REST API 全量端点

统一错误体 `{code, message, details[]}`；API Key 走 `X-Api-Key` 头。

### 4.1 mask-core（8080）

| 方法 | 路径 | 职责 |
|---|---|---|
| POST | `/api/rewrite` | 核心改写：`{metadataYaml \| instance, policyYaml?, sql, dialect?, user?, groups?}` → `{statements[], rewrittenSql}`；每请求恰一条 REWRITE 审计 |
| POST | `/api/rewrite/instances/{name}` | 面向查询数据面的实例级改写（元数据来自 metadata 快照 + 主体有效配置；fail-closed） |
| POST | `/api/config/parse` | metadataYaml → 编辑器结构（tables/columnPolicies/policies） |
| POST | `/api/policies/parse` | Ranger 式 policies.yaml 校验/解析（实现在 mask-policy，随 core 组件扫描挂载） |
| POST | `/api/metadata/pull` | 连活库（postgresql/mysql/trino）内省出 YAML 骨架；密码只用一次不落日志 |
| GET | `/api/audit/events` | ES 审计检索：`eventType/outcome/instance/resourceType/action/user/from/to/page/size`（窗口≤7天，size≤200；ES 不可用 502 `AUDIT_SEARCH_UNAVAILABLE`） |
| POST | `/admin/cache/refresh` | 清 instance 模式进程内缓存（body 可选 `{"instance": "..."}`） |
| GET | `/actuator/health` `/actuator/prometheus` | 健康 / Prometheus 指标 |

### 4.2 mask-policy-server（8081）

| 方法 | 路径 | 职责 |
|---|---|---|
| POST/GET | `/api/instances` | 创建实例（name/dialect/tables）/ 列表 |
| GET/DELETE | `/api/instances/{name}` | 详情 / 删除 |
| PUT | `/api/instances/{name}/tables` | 整体替换表清单（相同结构也推进 config_version） |
| POST/GET | `/api/instances/{name}/policies` | 创建策略（DATAMASK/ROW_FILTER）/ 列表 |
| GET/PUT/DELETE | `/api/instances/{name}/policies/{policy}` | 策略详情 / 更新 / 删除 |
| POST/GET | `/api/instances/{name}/udfs` | 注册 UDF（名称+签名列表，支持重载）/ 列表 |
| GET/PUT/DELETE | `/api/instances/{name}/udfs/{udf}` | UDF 详情 / 整体替换 / 删除（删除使策略失效会被拒） |
| POST | `/api/instances/{name}/import-metadata` | 从元数据服务导入表结构（自动建实例/整体替换，校验方言一致） |
| GET | `/api/effective/{instance}?user=&groups=` | 按主体编译的生效配置（无参=匿名）；每次拉取发 EFFECTIVE_PULL 审计 |
| GET | `/actuator/health` `/actuator/prometheus` | 健康 / 指标 |

UDF 签名校验：UDF 存在、参数个数（= arguments + 1 列值）、标量类型族匹配
（number→整数/浮点/numeric，string→字符族，boolean）、选中列类型与某重载首参精确相等。

### 4.3 mask-metadata（8082）

| 方法 | 路径 | 职责 |
|---|---|---|
| POST/GET | `/api/instances` | 创建实例（name/dialect/engine/connection）/ 列表 |
| GET/PUT/DELETE | `/api/instances/{name}` | 详情（含连接与表结构）/ 更新连接 / 删除 |
| POST | `/api/instances/import` | 导入 metadataYaml（只吃 `metadata.tables`；带 rowFilter 的表声明 400 拒绝） |
| POST | `/api/instances/{name}/collect` | 用存储的连接引用触发在线采集（不接受请求携带密码） |
| GET | `/api/metadata/instances` | 数据面实例列表（供 policy/query 消费） |
| GET | `/api/metadata/instances/{name}` | 数据面快照（tables 刻意不含 rowFilter——策略域数据） |
| GET | `/api/metadata/instances/{name}/version` | 当前元数据版本 |
| GET | `/actuator/health` `/actuator/prometheus` | 健康 / 指标 |

`hive`/`sparksql` 方言实例不支持采集（显式拒绝，不计 FAILURE 指标），只能 YAML 导入。
密码只登记环境变量名（`passwordRef`，推荐 `SQLMASK_DS_<INSTANCE>_PASSWORD`），
采集时服务端本地解析；不落库、不进日志。

### 4.4 mask-query（8083）

| 方法 | 路径 | 职责 |
|---|---|---|
| POST | `/api/v1/query` | `{instance, sql, user?, groups?, maxRows?, includeRewrittenSql?}` → `{columns, rows, rowCount, truncated, masked, rowFiltered, elapsedMs[, rewrittenSql]}`；仅单条 SELECT（`MULTI_STATEMENT`/`WRITE_STATEMENT` 拒绝） |

引擎目录与护栏：postgresql/mysql/starrocks(复用 mysql 方言)/trino/hive/sparksql；
超时 30s、默认 maxRows 1000、硬上限 10000、每实例并发 10（超出 `QUERY_BUSY` 快速失败）；
Hive/SparkSQL 时间护栏以容器兜底超时为主路径（驱动 setQueryTimeout 支持不全）。

## 7. 审计与指标

- **审计**（mask-core/mask-metadata，异步尽力而为，ES 故障不影响业务）：
  事件 `REWRITE`/`ADMIN_CHANGE`/`EFFECTIVE_PULL`（`QUERY` 事件由 mask-query 链路产生）；
  索引按 UTC 日滚动 `mask-audit-YYYY.MM.dd`；SQL 超 8192 字符截断打标；
  队列满丢弃；查询走 `GET /api/audit/events` 固定条件接口（不做 DSL 透传）；
- **指标**：`/actuator/prometheus`（core 8080、metadata 8082、policy-server 8081 同端口暴露），
  前缀 `sqlmask_`；mask-query 无 actuator。端点无鉴权，仅限内网。

## 11. 已知边界（当前版本有意保留）

- 单 jar（mask-core）不含策略管理面（在 8081）；core 上 `/api/instances`、`/api/effective`
  只有 filter 分支无 controller（重构计划 B4 待删）；
- 页面导入弹窗标题仍写「连接 PostgreSQL」但引擎下拉框三引擎均可用；
- CLI `--connect-timeout` 对 Trino 无效（驱动不支持该 URL 属性）；
- MySQL UDF 字符串参数中的反斜杠不双写（策略参数尽量避免）；
- `BETWEEN SYMMETRIC` 按 Calcite 原渲染输出（仅 PostgreSQL 可执行）；
- 一个输出表达式多来源列时按字典序选策略（不表达业务优先级）；
- 聚合列绑文本型策略需要 UDF 有对应类型重载（如 `mask_phone(bigint, integer, integer)`）；
- `top`/`overwrite` 作函数调用的写法按 `PARSE_ERROR` fail-closed 拒绝；
- CTE 主体内引用同名 CTE 一律按递归 CTE 拒绝（真实 PG/MySQL 可能按基础表解析）；
- mask-engine / mask-common 为重构中的新模块，尚未接线（仅自身 pom 引用）。
